    Delivery, credentials and measurement limits
    RTMP destinations share one encode per orientation: Landscape is 16:9 and Portrait is 9:16. Both orientations require separate encodes. Each additional destination still uses a connection and uplink bandwidth. Recording and other transports may need additional encoders.
    Custom RTMP carries picture and sound, not automatic platform titles, audience chat or analytics. Set those on the receiving platform. This build locks route changes during a run or unresolved cleanup; live channel hot-add/remove is not implemented.
    Dropped frames and reconnect counts are not shown because this build cannot measure them: framesDropped is read from a WebRTC stat where the specification defines no such member, and there is no reconnect policy to count. A zero in either column would be a number we had invented.
    Stream URLs, keys and account connections are held in memory until this session closes. They must be entered again for a new session.
